## 🧠 Leçons de plateforme (à ne plus retester)

> Auditées le 09/09 : chaque leçon porte sa preuve (types pi, doc, ou code v0.12 validé TUI).
> L'ex-leçon « BOM PowerShell » est écartée → `discovery_SessionHub.md` F-01.

1. **Le pouvoir de switcher appartient au ctx command, jamais au ctx event** (fusion ex-1 + ex-9 + ex-11, audit 09/09) — au typage, `switchSession` n'existe que sur `ExtensionCommandContext`, pas sur `ExtensionContext` (types pi). À l'exécution : la commande `/hub` ET le shortcut ctrl+h l'exposent (testé TUI par Impre), `session_start` jamais. Pattern du hub : `getSwitch(ctx)` runtime-check → switch direct ; sinon fallback `pi.sendUserMessage("/hub <id>", { deliverAs: "followUp", expandPromptTemplates: true })` — pi exécute la commande avec un ctx command, zéro action user. Aucun submit programmatique dans l'API UI (`pasteToEditor`/`onTerminalInput` oui, submit non). Preuves : types.d.ts (ExtensionContext l.209 sans switchSession, ExtensionCommandContext l.254 avec) + code v0.12 validé TUI.
2. **Le braille Unicode se rééchantillonne comme une image** (ex-3) — decode 2×4 dots → box-average → re-encode (`tools/braille-resize.mjs`) ; les dots braille sont ~carrés en terminal, le ratio se conserve au niveau dots. Preuve : l'algo décrit est littéralement dans l'outil (l.8).
3. **La capture souris n'est active qu'en mode fullscreen** (ex-4) — en regular, le terminal garde le scrollback. `handleMouse` s'implémente quand même : inerte en regular, actif dès la bascule. Preuve : `settings.md` (tuiMode regular|fullscreen) + `keybindings.md` (souris/scroll traités en fullscreen).
4. **`TuiMouseEvent` (x, y) est local au composant récepteur** (ex-5) — pour forwarder à un enfant rendu dans une sous-zone, retarget manuel (shift x/y) avant `handleMouse` enfant. Preuve : pi-tui `tui.d.ts` l.16 « Coordinates local to the receiving component » (+ screenX/screenY absolus).
5. **`ctx.setHeader` se rejoue à chaque `session_start`** (ex-6) — un replacement de session (switch) re-fire `session_start` : un seul handler gère les deux modes (hub sur home, logo ailleurs). Preuve : `extensions.md` l.432 — switch → session_shutdown → reload → session_start (reason new|resume).
6. **Mode overlay** (ex-7) : `ctx.ui.custom(factory, { overlay: true, overlayOptions })` — anchors `top-center` etc. Le hub connaît la hauteur du terminal via `tui.terminal.rows` : filler calculé dans le render pour ancrer les options juste au-dessus de la chatbox (`CHATBOX_H`). Preuve : types.d.ts l.122-124 + usage validé TUI.
7. **Cas d'école (08/09) : empiler des features sans valider le socle à chaque étape rend tout le lot invérifiable** (ex-10) — quand le switch (socle) a cassé en v0.7/v0.8, les features empilées par-dessus (mode jaune, ctrl+h, sons…) n'étaient plus valables individuellement. Règle renforcée : UNE feature par commit, validée en TUI par Impre AVANT le commit suivant — même si ça ralentit, c'est le seul chemin sans zigzag. Preuve : l'incident lui-même (git log 08/09) — process, non re-testable.
8. **Changement d'art = une commande** (`use-art.mjs`) (ex-8) — `ART_W` est dérivé du tableau injecté, le layout se recalcule tout seul. Les assets originaux sont archivés dans `dev/` : rollback en relançant l'ancien fichier. L'autocrop (bounding box des dots) préserve la résolution quand l'art source a des marges vides. Preuve : use-art.mjs l.25/29/71.
9. **`SessionManager.create()` est lazy : le .jsonl n'existe pas au retour** (10/09) — le header n'est écrit qu'au premier append. Tout `switchSession` vers ce fichier fraîchement créé → `SessionManager.open()` ne trouve pas de header (`existsSync`=false) → retombe sur `process.cwd()` (le chemin d'ouverture de pi) : session au mauvais endroit, header contaminé (fichier au bon groupe MAIS cwd du header faux). Contournement : flusher le header officiel avant le switch (`createFlushedSession()` : `writeFileSync(file, JSON.stringify(sm.getHeader()))`). Preuves : logs hub-diag 10/09 (`fileExists=false`), session du 09/09 22:20 (fichier groupe zoo-code, header `C:\Users\Pelo`, `pwd`=/c/Users/Pelo), script de reproduction (avant `false` → après `true`, `open().getCwd()`=workspace). NB : `ctx.switchSession` n'expose pas `cwdOverride`, et `handleResumeSession` ne le forward de toute façon pas (interactive-mode l.4507).
10. **Reverse de calibrage = diff complet source ↔ install AVANT le `cp` de sync** (12/09) — fait : reverse partiel d’un calibrage Impre (grep ciblé sur `BODY_OFFSET_*` seulement) a raté `LIST_DROP`/`LIST_WIDTH` retunés dans l’install ; le `cp` de sync a écrasé les calibrages et le push v0.15 est parti avec des valeurs non validées (9/30 au lieu de 10/20). Conséquence : la git history contient un état jamais constaté en TUI, réparé en v0.15.1. Contournement : avant tout `cp source → install`, `diff source install` — tout écart non expliqué par les edits en cours = calibrage non reversé → STOP, reverse d’abord.
11. **Architecture overlay du hub : le base layer est scrollé, la row 0 échappe au hub** (12/09) — le hub est un calque composité par-dessus le document pi (compositeOverlays, tui.js) ; il ne couvre que `viewportStart+margin → +height` et le clamp `row = Math.max(marginTop, …)` interdit d’atteindre la row 0. En discussion, le document est scrollé (`viewportStart = result.length - termHeight`) → la row 0 non couverte tombe dans le transcript (header hors écran) = la ligne fantôme. margin 0 couvrirait la row 0 MAIS déclenche des effets de bord globaux (caret visible + décalages en discussion, 2 tests TUI 12/09, mécanisme non élucidé) → ne pas retenter sans labo pi-tui. Voie officielle : contrôler le base (header vide + scrollTo(0)) et restaurer à la fermeture. Preuves : tui.js resolveOverlayLayout/compositeOverlays/doRender + 3 tests TUI 12/09.
12. **Le caret hardware = CURSOR_MARKER émis par le composant focusé** (12/09) — l’éditeur émet un marqueur APC (`\x1b_pi:c\x07`) à la position du curseur quand focused ; extractCursorPosition cherche le marqueur dans l’image FINALE compositée et positionne le caret (`?25h` si trouvé, `?25l` sinon). Toggle global : setShowHardwareCursor(false) → `?25l` à chaque frame, même si un marqueur traîne. Preuves : tui.js l.49-54 + 978-1004 + doRender l.1481-1487 ; components/editor.js l.426-439 (marker émis si this.focused).
13. **Le diff-painting skippe les lignes identiques — jamais d’écriture ANSI externe** (12/09) — doRender ne repeint que `screen[row] !== previousScreen[row]` : toute écriture ANSI externe (writeSync) diverge du previousScreen et n’est jamais réparée si la ligne logique ne change pas (row 0 vidée définitivement au retour discussion). Preuve : tui-alt-screen.js doRender l.1478-1482 (lecture code ; constat cohérent avec les symptômes margin 0).
14. **Tout scroll programmatique du transcript déclenche la scrollbar transitoire** (12/09) — scrollTo/scrollBy/scrollToEnd appellent markScrollbarActivity : si `scrollbar === "auto"` (défaut) et contenu > viewport, la scrollbar s’affiche ~2s (scrollbarHideDelayMs) — le « trait fin bref » constaté par Impre à l’ouverture du hub. Contournement : setScrollbar("hidden") AVANT les scrolls (le setter masque l’immédiat sans re-déclencher), restore du mode d’origine après. Preuves : scroll-view.js l.57-66 (setScrollbar) + l.70-83 (markScrollbarActivity) + TUI 12/09.
